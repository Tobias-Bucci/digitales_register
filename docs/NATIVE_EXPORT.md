# Native data export — Issue #12

## Entry points and formats

Settings → **Daten exportieren** opens the native Flutter export page. Certificates and
messages also have an app-bar shortcut; grades have an inline export action. All open the same page/service.
The existing theme, localization catalogs and native file picker are reused.

All eight categories support PDF and UTF-8 CSV: certificates, grades, messages,
timetable, calendar assessments/dates, calendar tasks, absences, and lesson content.
Selecting multiple categories creates a single PDF with a section per category,
or a ZIP containing one CSV per category. CSV includes a BOM, semicolon delimiter,
CRLF records, quoted/escaped cells and formula neutralization. Grade CSV includes
subject and overall averages. Decimal formatting follows the selected language.

Options include loaded school years, inclusive date range, grading semester,
subject, and individual entry selection. Inapplicable filters are hidden/ignored;
certificate content is not assigned an inferred year or semester.

## Data contract and limits

Opening the export page refreshes grades (both semesters), messages, certificate,
absences, dashboard and calendar data through the existing middleware,
without navigating those pages. A progress state blocks saving until hydration
finishes; failed/offline loads allow explicit retry and retain cached data. Refresh
requests are scoped to the mounted account. Grades loading now awaits semester
requests instead of returning before they complete.

Exports freeze one immutable account snapshot. Historical years are offered only
when dated entries for them exist. Export explicitly hydrates missing weeks of the
current school year for assessments/tasks, combining responses into one reducer
update. It does not hydrate other historical years. The timetable selects only
one representative week from these actual data. There is no new historical API.

The grade projection rebuilds filtered Subject models and calls `Subject.average`
and the canonical `overallGradeAverage`; it does not implement another weighting
rule. Cancelled and missing grades remain visible but follow the existing average
rules. Configured exclusions still apply to the overall average. Both semester
and date/entry selection constrain the averages. Refreshing source data resets
index-based selections to prevent a newly inserted grade being selected by mistake.

The timetable is one actual, complete teaching week chosen from cached/refreshed
weeks, preferring the fewest detected substitutions/cancellations/special events.
It is rendered as a landscape day-by-period grid. Other calendar and attendance
categories use compact tables. Messages retain full text. CSV uses a fixed useful
schema per category (no internal IDs or empty duplicate title/content columns),
ISO dates, full timestamps for messages/deadlines and localized headers/numbers.

Calendar tasks/assessments are deduplicated by their register ID; timetable lessons
retain their actual dates, periods, available times, teachers and rooms. Absences
retain individual dates and durations, falling back to group information where
necessary. Missing values remain empty. Calendar dates preserve school wall time
according to the app's UtcDateTime convention, without an extra timezone conversion.

Register messages support Quill Delta JSON as well as legacy HTML/plain text.
Script/style content is removed and no media URLs are fetched. Attachments and
lesson materials are listed **by name**, not downloaded or embedded. Certificates
preserve available HTML text and tables as a **personal overview, not an official
school report**. Images, signatures, seals and original HTML styling are excluded;
the current model exposes HTML rather than an original signed certificate file.

Creation is offloaded to worker isolates on native targets. PDFs use locally
bundled Noto Sans regular/bold (SIL OFL), A4, repeating headers/footers, global page
numbers and bounded text/table fragments without content truncation. There is no
font download. Resource limits (20,000 records or 10 million content characters)
produce an actionable error asking for a narrower selection.

## Privacy and platform handling

The export feature adds no analytics events, network services or personal-data
logs. Generated bytes remain in memory until the user chooses the destination
through file_picker. Cancellation and write failures are distinct outcomes.
Exports are user-controlled copies outside the app's cache/logout deletion policy;
the page explains their sensitive nature. A disposed/switched account cannot open
a save dialog for an export still being generated.

- Android: existing Storage Access Framework create-document flow; no new storage permission.
- iOS: existing document exporter; bundled plugin patch stages into a UUID-named
  temporary directory rather than Documents and removes it on success, cancel,
  dismissal or preparation failure. A process kill can leave OS-managed temporary
  data until iOS reclaims it. See the patch note in packages/file_picker/README.md.
- Windows/Linux: existing native save dialog writes supplied bytes itself; the
  application does not perform a second write or treat a cancelled dialog as success.
- macOS: user-selected read/write entitlement added to both configurations, allowing
  the sandboxed save panel to write only the location chosen by the user.

## Implementation map

- `lib/export/export_data.dart`: pure model projection, filters, HTML/Delta text.
- `lib/export/export_pdf.dart`: typography, tables and pagination.
- `lib/export/export_csv.dart`: localized CSV and spreadsheet safety.
- `lib/export/export_font.dart`: UTF-16BE character maps, including supplementary emoji; remove the isolated workaround when upstream pdf fixes its Unicode map.
- `lib/export/export_service.dart`: worker dispatch, limits, ZIP and native save.
- `lib/container/export_container.dart`: account-scoped Redux connection/navigation.
- `lib/ui/export_page.dart`: category selection, options, preview counts and status.
- Four locale catalogs, bundled licensed fonts, settings/detail entry points,
  iOS staging patch and macOS entitlements complete the integration.
